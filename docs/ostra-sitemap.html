Ostra Studio · Website brief v1.0 · Deliverable 1

One shallow, quiet structure.

Four top-level pages, three levels at most, and every page tied to an audience action. Items beyond the brief are marked as recommended additions.

How the structure balances goals, users and build

Business goal

Lead generation. The site exists to move qualified people to a consultation or a credentials request. Success metrics from the brief: inquiry conversion rate, share of inquiries matching target budget and project type, Lighthouse 90+ on mobile, organic growth over six months.

Audiences and tasks

Residential clients want proof of delivery and a consultation. Developers and institutions want scale, process and credentials. Press and talent want assets, awards and jobs. Each has a path of three page loads or fewer.

Shape

Home plus Work, Studio, Journal and Contact, with no dropdown menus. Depth stops at three levels. The only third-level pages are case studies, open roles and category listings that hang off an index.

Scalability

Projects, articles and roles are repeating templates fed by the CMS, so growth adds URLs without changing the structure. A new line of work needs only a new type value.

Technical

Clean lowercase URLs, one canonical per page, XML sitemap generated from the CMS. Launch size is far below the 50,000 URL and 50 MB limits for a single sitemap file.

Decisions worth challenging

No dropdown menus

Studio sub-pages are reached from an in-page index and the footer. This keeps the header to four items and one call to action, in line with the brief's restraint.

Category pages use a reserved path

Types live at /work/category/[type] and tags at /journal/category/[tag], so they can never collide with a project or article slug.

"In Progress" is a status, not a page

The brief lists it as a filter beside four project types. It stays a filter on /work and canonicalises to /work, because a thin, changing page is poor search value.

Case study sections are anchors

Imagery, plans, materials, metrics, narrative and credits sit on one URL. Splitting them would multiply thin pages and break the monograph reading flow.

A credentials page is added

The brief gives developers a "request credentials" action but no page for it. A short form at /contact/credentials gives that path a clear destination and its own conversion tag.

Sheet 4 · URL, indexing and schema rules

One canonical for every page.

Rules

URL format

Lowercase, hyphenated, no dates, no file extensions. Slugs are set once and redirected if they ever change.

Canonical and parameters

Filter and sort parameters on /work and /journal canonicalise to the clean index URL.

Noindex

Thank-you pages, closed roles and any category page holding fewer than three items.

Redirects

Old URLs map one to one with 301s at launch. Trailing slashes are normalised.

XML sitemap and robots

/sitemap.xml generated from Sanity at build - indexable URLs only (noindex pages excluded) - lastmod from the document's updated date - image entries for project imagery /robots.txt allows all, points to /sitemap.xml disallows /contact/thank-you Submit in Google Search Console and Bing Webmaster Tools. Split into an index file only if a file nears 50,000 URLs or 50 MB (not a launch concern).

Page titles follow "[Page] | Ostra Studio". The home title and LocalBusiness markup need the studio's city, which is an open item.

Sheet 6 · Validation plan

Test the tree before code.

This structure has not been tested with users. Run a tree test on the sitemap alone, then a short card sort for Journal categories.

Tree-test tasks

Method and pass marks

Participants

About 15 per audience: people who commission houses, developer or institutional clients, and architecture or design professionals.

Pass mark

At least 80 percent of participants reach the right page without backtracking on each task. Below 60 percent, restructure that branch.

Card sort

Open sort of 20 sample articles to confirm the three Journal categories, or find better ones.

Stakeholders

Review with the partners, business development, project managers for case-study data, HR for Careers, and whoever handles press.
